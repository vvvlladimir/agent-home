## 1. Drafts depend on a helper the house does not have (major)

**What happens.** The house finds the habit correctly. The owner switched `light.kitchen_counter` on around 06:50 and off around 07:35 on workdays, and on house day 4 (11-19 04:30, the daily review) the house drafted "Kitchen Counter light, morning on and off" with `at: 06:51` / `at: 07:36`. The draft has a condition on `input_select.agent_house_mode`. That helper does not exist in this house: nobody created it, and `auto_house_mode` is off. HA treats a state condition on a missing entity as false, so this automation never runs. The add-on's checks (`yaml`, `schema`, `policy`, `ha_validate`) all pass, because none of them checks that the entities exist.

It is systematic, not one bad draft: all 5 drafts of the run name the missing helper (Bedroom lamp, Living room TV, Kitchen ceiling, Living room lamp, Kitchen counter). Run 4 showed the same in QA-004 (hands_off_owner) and QA-002 (fussy_tenant, there `sensor.living_room_motion_illuminance`).

**Evidence** (proposal `p_1a1f2120242ca5844`, run `morning_counter_habit-7`):

```yaml
conditions:
- condition: not
  conditions:
  - condition: state
    entity_id: input_select.agent_house_mode   # not in HA
    state: away
actions:
- choose:
  - conditions: [{condition: trigger, id: 'on'}]
    sequence: [{action: light.turn_on, target: {entity_id: light.kitchen_counter}}]
  ...
```

The invariant `proposals_known_entities` (sim/invariants.py) flags all 5, with the house time each was drafted.

**Likely cause.**
- The model is told to use the helper unconditionally: `agent_house/app/core/orchestrator.py:106` ("The house mode is input_select.agent_house_mode … Prefer a …") and `agent_house/app/core/habits.py:398` (the dossier suggests conditioning on "the house mode input_select.agent_house_mode").
- The draft checks in `agent_house/app/core/lifecycle.py:131-324` never compare the entity ids in the YAML with HA's states.

**Expected.**
1. A draft that names an entity HA does not have is `blocked`, with the missing ids in its checks.
2. The orchestrator and the dossier mention the house-mode helper only when it exists.

**Reproduce.**
- With real models (about 50 min): `python -m sim.stories run --story morning_counter_habit --k 1 --room-llm claude --orchestrator claude --no-pace`.
- Faster: restore `.agent-logs/stories/20261114-135906/morning_counter_habit-7/snapshots/` (the day-4 or later snapshot) with `python -m sim.polygon serve --restore <folder>`, then `GET /api/proposals`.

**Owner:** core-engineer (`orchestrator.py`, `habits.py`, `lifecycle.py`; the lifecycle change needs the reviewer).

## 2. A leak in a room without an agent reaches no one (major)

**What happens.** The polygon's agents are bedroom, hallway, living_room and kitchen. Each has a wake rule for `binary_sensor.*_water_leak` (`sim/polygon.yaml:18,29,38,47`). The bathroom leak sensor `binary_sensor.bathroom_leak_sensor_water_leak` went `on` on house day 2 at 11:20 for 6 min:
- no agent woke;
- the feed has no line about it;
- the inbox got nothing.

**Cause** (deterministic, no model involved). The wake gate only wakes an agent for entities in that agent's scope: `agent_house/app/core/gate.py:117` (`if entity_id not in self.scope_of(agent): continue`). The bathroom sensor is in no agent's scope, so the house-wide leak rule never fires. The house manager is off by default, and it sweeps hourly in any case. No safety path covers leaks or smoke house-wide.

**Expected** (owner's decision, a product question). One of:
1. alarm-priority rules (leak, smoke) match house-wide, whatever the scope;
2. a deterministic safety path writes an inbox alarm for every leak/smoke sensor;
3. the owner is warned at setup that rooms without an agent are not watched.

**Reproduce** (fakes, about 30 s): `python -m sim.stories run --story leak_unwatched_room --k 1`. Expect `report_about … 0/1 … missed at <day 2 15:05>`.

**Owner:** core-engineer (`gate.py`), after the owner decides on the expected behaviour above.

## 3. A workdays-only habit becomes an every-day automation (minor)

**What happens.** In the story the habit happens Mon–Fri only. The daily review's own text tells workdays and weekends apart for other devices ("Kitchen Ceiling: on Mon–Fri about 06:44 and Sat–Sun about 08:26"). The kitchen-counter draft, though, has two `time` triggers and no weekday condition, so it would switch the counter light on at 06:51 on Saturdays and Sundays too.

**Expected.** A habit seen only on workdays gets `condition: time` with `weekday: [mon, tue, wed, thu, fri]`. The orchestrator gets the weekday split in the dossier (D31 §3).

**Reproduce:** same run and proposal as bug 1 (`p_1a1f2120242ca5844`).

**Owner:** core-engineer (`habits.py` dossier text and the orchestrator's drafting prompt). Proposed check for the stories: a `weekday_respected` expectation (not written yet).
